# EAD 2026 Registration & Badge Printing System — Outcome ToDo

- [x] **Public registration and confirmation flow:** Build the primary flow as Register → Confirm → Generate Badge → Preview → Print, designed to complete registration in under 30–45 seconds and optimized for a physical registration desk. The registration screen immediately communicates “Egypt Arbitration Days 2026” and “12–15 October 2026”. The form contains only Full Name (“Enter your full name”), Company (“Enter your company”), Title (“Enter your title”) and Email (“Enter your email”), with “Complete Registration” as the primary CTA. On success, validate and save a unique attendee, show “Registration Complete”, “Welcome to Egypt Arbitration Days 2026.”, a summary of Name/Company/Title/Email, “Badge Ready”, a live badge preview, “Print Badge”, and “Register Another Attendee”. Register Another Attendee instantly resets the form for high-volume processing.

- [x] **Form interaction, duplicate handling and errors:** Use large comfortable inputs and appropriate responsive/touchscreen layouts. Include smooth input focus, clear validation messages, required indicators, email validation, protection against accidental double submission, loading state, disabled submit while processing, smooth confirmation transition, appropriate first-field autofocus, keyboard-friendly navigation and natural Enter submission. If the same email already exists, show a human-friendly message such as “An attendee with this email is already registered.” and provide “View Registration” and “Register Another Person”. Never expose technical server errors; show friendly retry/network-failure messages including “Something went wrong. Please try again.” and “Connection lost. Your registration has not been submitted. Please check the connection and try again.”

- [x] **English/Arabic localization and RTL:** Support English and Arabic throughout the entire application, with a highly visible “EN | العربية” switcher and persisted language preference. Arabic is a true RTL experience: direction, form alignment, navigation, buttons/icons, typography and badge text all adapt appropriately; do not merely translate text while retaining the English layout. Keep Arabic typography elegant, readable and accessible.

- [x] **Reusable physical badge and design preview:** Use the supplied reference artwork as the physical badge’s exact structural reference and respect the EAD visual language without randomly redesigning the badge or distorting/recreating the logo. Implement a reusable template accepting name, company, title, email, language and registrationId; attendee data is dynamic. The ID badge is exactly 7.4 × 10.5 cm with front and back. Front/name-tag face: preserve the EAD red header and bottom motif, and place dynamic attendee Name, Company, Title and registration ID inside the supplied white center. Back/event-art face: preserve the original blue EAD event artwork and dates without attendee text over it. Preview and print show front first and back second, with realistic physical proportions, front/back toggle, zoom, print preview, attendee details, EAD branding and correct Arabic text when selected; subtle 3D treatment is allowed only if professional. Keep the template separate from the registration form so it can change independently.

- [x] **Lanyard preview:** Include a separate visual preview in the admin/design system for the specified 50 × 1.5 cm lanyard, using the EAD branding pattern from the supplied artwork and repeating the EAD logo naturally. The lanyard is not editable during registration.

- [x] **Print flow and status:** Provide a dedicated “Print Badge” action that opens a badge preview including front/back, paper dimensions and correct print scale. Printed size must remain exactly 7.4 × 10.5 cm with correct aspect ratio. Use print-specific CSS (`@media print`, physical dimensions, zero page margins), render artwork as image elements, exclude browser/app/dashboard/navigation UI and remove print shadows; the PDF/output must contain exactly two non-repeated pages per badge, front first and back second. After print, show “Badge Printed Successfully” with attendee name, printed time and badge preview, then offer “Register Another Attendee” as the primary next action. Store printed status and timestamp; allow reprint without creating a duplicate registration.

- [x] **Secure staff/admin area and overview:** Provide a separate staff interface protected by login and authorization. Regular attendees must never access registration data, other attendees, dashboard or badge management. Admin navigation includes Dashboard, Registrations, Badge Printing and Settings; Settings contains event information, badge template, language and printing settings. Overview statistic cards show Total Registrations, Today’s Registrations, Badges Printed and Pending Prints, with elegant event-appropriate styling.

- [x] **Registration management, search and high-volume workflow:** Provide a registrations table with Name, Company, Title, Email, Registration Time, Badge Status and Actions. Badge status values are Not Printed and Printed. Actions include View, Edit, Print and Reprint. Provide instant search by Name/Company/Email, filters, sorting and pagination. Staff can open a registration, see attendee details, edit information, save changes and reprint without duplication; the badge preview updates after edits. Include polished empty/no-results states. Fast Registration/Registration Desk mode focuses the interface on continuous attendee processing; after printing it can automatically return to a blank form. Provide Ctrl/Cmd+N for New Registration and Ctrl/Cmd+P for Print Badge where appropriate.

- [x] **Persistence, responsive design, accessibility and performance:** Store Registration records with id, name, company, title, email, language, registeredAt, badgePrinted, badgePrintedAt and updatedAt. Validate data and enforce unique email unless an administrator explicitly overrides it. Optimize for desktop, laptop, tablet and mobile; tablet registration is especially important. Mobile form is single-column with large touch targets, no horizontal scrolling and sticky CTA where appropriate; mobile admin navigation uses a compact menu or bottom navigation. Desktop intelligently uses space and may place the form beside an EAD panel and badge preview. Support keyboard navigation, visible focus, proper labels, sufficient contrast, screen-reader-friendly fields and RTL accessibility. Prioritize fast initial load/submission/badge rendering, instant filtering and responsiveness with thousands of registrations; keep animation subtle and non-distracting.

- [x] **EAD-specific visual design and motion:** The system is specifically for Egypt Arbitration Days 2026, not a generic SaaS dashboard. Draw from the official EAD site and supplied artwork: deep burgundy/dark red, white, warm off-white, dark charcoal and restrained neutrals; premium, international, legal, editorial, sophisticated, modern, minimal and confident. Preserve authentic EAD logo proportions and clear space. Use refined typography with Arabic support, generous whitespace, restrained borders/shadows, tactile buttons and consistent elegant radii. Avoid Bootstrap defaults, generic Tailwind dashboard appearance, excessive bright colors, gradients and glassmorphism. Add polished short microinteractions for focus, buttons, loading, success, badge generation/preview, front/back, dashboard cards, table rows and modals; do not overdo motion.
- [ ] **Portable local project delivery:** Transfer all project files—including source, components, assets, package/config files, database/schema/migrations, environment/config templates, public/static files and every other file required to run—to a local folder on the authorized user device, preserving the full directory structure; do not leave the final version only in the workspace. Before finishing, verify the files copied completely and the project can still be installed and run from that copied location. Never transfer live environment secrets.
